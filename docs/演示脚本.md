# 工业固件安全升级分发系统 —— 答辩演示脚本

| 项 | 内容 |
|---|---|
| 文档版本 | v1.0（2026-11-18，答辩前一天） |
| 时长 | 正式演示约 10 分钟，另备 3 个可选场景应对提问 |
| 演示机 | macOS（已在真机验证构建和单台升级）。Linux 同样可用；Windows 没有一键脚本，按 README“手动联调”操作 |
| 配套 | `demo/` 下的一键脚本（准备、启动、停止、重置、篡改审计），用法见 [README](../README.md)“答辩演示” |

演示的原则：**每个场景都能从 `demo/reset.sh` 的初始状态单独开始**，任何一步卡住都不硬救，重置后跳到下一个场景（重置加启动约 20 秒）。

## 1. 演示前准备

### 1.1 前一天晚上（约 20 分钟，只做一次）

1. 拉最新的 `main`，重新构建。macOS 上换过 Qt 或 OpenSSL 一定要先删构建目录（Homebrew 的 Qt 6.12 改用 OpenSSL 4，旧缓存会指向错的库）：

   ```sh
   git pull
   rm -rf build/dev
   cmake --preset dev -G Ninja && cmake --build --preset dev
   ctest --preset dev            # 可选，约 1 分钟，全部通过即可
   ```

2. 准备演示数据：`demo/setup.sh`。它只问两个口令：**演示密钥口令**（至少 12 个字符）和**演示账号口令**（至少 10 个字符，含字母和数字）。两个口令写在纸上，两个人都要知道，不要存进电脑里的任何文件。许可证绑定本机硬件指纹，所以必须在演示用的那台电脑上运行。
3. 完整彩排一遍第 2 节，计时。彩排完运行 `demo/reset.sh`。
4. 把第 4 节的兜底截图放进一个文件夹，桌面上留快捷方式。

### 1.2 答辩前 30 分钟

1. 电脑：接电源；打开“勿扰模式”；关闭自动睡眠和屏幕保护；关掉无关程序（尤其是会弹通知的聊天软件）。投影时把显示器缩放调到字能看清。
2. 终端在仓库根目录，字号调大，然后：

   ```sh
   demo/reset.sh && demo/start.sh      # 输入演示密钥口令
   ```

   看到“全部在后台运行”后，服务端窗口弹出登录框。
3. 摆窗口（macOS 上被完全挡住的 Qt 窗口不会重绘，看起来像卡住，所以窗口之间尽量不要重叠）：
   - 左边 2/3：服务端主窗口；
   - 右上：DEV-001 窗口；右下：DEV-002 窗口；
   - 终端缩小放在右下角或单独一个桌面，只在场景 5 用一次。
4. 服务端用维护员 `maint01` 登录，确认“设备监控”页 4 台设备都在线、心跳时间在跳。**先不要打开“允许下发”**，这是场景 1 的内容。
5. 终端里预先敲好 `demo/tamper_audit.sh`，先不回车。

## 2. 正式演示（约 10 分钟）

每步的格式：**操作** → 屏幕上应该看到什么 → 讲什么。讲稿是要点，用自己的话说。

### 场景 0：总览（0:00 – 0:45）

- **操作**：停在服务端“设备监控”页。
- **看到**：4 台设备在线，型号 PLC-X200，固件 2.0.0，最后心跳时间每 5 秒刷新，登录状态“已登录”。
- **讲**：
  - 系统有三个程序：离线签发工具（建 CA、签证书、给固件签名）、分发服务端、设备客户端；现在本机开了 4 台模拟设备，DEV-002 走一条限速 2 MB/s 的“慢速链路”。
  - 严格 C/S 桌面程序，所有通信都在 TLS 1.3 双向证书认证的信道里，只开 `TLS_AES_256_GCM_SHA384` 一个套件；信道上是我们自己的二进制帧协议，帧头 Length 先校验再分配内存，帧序号必须连续。
  - 心跳 5 秒一次，15 秒收不到判离线。

### 场景 1：只读优先和权限分离（0:45 – 1:45）

- **操作**：点右上角“允许下发” → 弹确认框 → 确认。然后“退出登录”，用操作员 `oper01` 登录。
- **看到**：开关变为打开；操作员界面没有账号管理、设备注册这些维护员功能。
- **讲**：
  - 系统默认只监控，不下发；“允许下发”只有维护员能开，每次服务端重启都回到关闭（检查项 7-1）。
  - 三个角色：维护员管设备、固件库和开关；操作员只能发布固件；审计员只能看和校验审计日志，互相不能越权（ST-12）。
  - 账号口令用 PBKDF2-HMAC-SHA256、60 万次、每个账号 16 字节随机盐保存，不是一次 SHA-256（红线 1-2）。

### 场景 2：正常升级与实时进度（1:45 – 3:15）

- **操作**：“固件库”页选中 2.1.0 → “下发到设备…” → 选 DEV-001 → 确认 → 弹出口令框，输入 `oper01` 的口令。然后切回“设备监控”页。
- **看到**：DEV-001 的升级状态依次是下载中、校验中、写入中、重启中（停 8 秒），最后 `SUCCESS`，固件版本变为 2.1.0；DEV-001 窗口里活动分区从 a 变成 b。
- **讲**（边等边讲）：
  - 下发是控制指令，执行前要再输一次口令（二次确认，10-2），操作者、时间、来源都进审计日志。
  - 设备先拿到签名的 manifest，**先验 RSA-3072-PSS 签名、再查型号、再查安全版本号**，三项都过了才开始要分片；每一片都按 manifest 里的 SHA-256 校验，不符就重要。
  - 下载完写 Flash 之前，整个镜像再从头算一遍哈希、签名再验一遍：防的是镜像在磁盘上躺着的时候被改。
  - 新固件只写**备用分区**，正在运行的分区不动；重启后 Bootloader 验签加自检通过才“转正”，转正后才提高最小安全版本号。

### 场景 3：坏固件自动回滚 + 断网事件补传（3:15 – 5:15）

> 和场景 2 至少隔 10 秒再下发（互锁：刚下发过的设备要等它在心跳里报上新状态）。

- **操作**：
  1. “固件库”页选中 2.2.0（这是一个自检必定失败的包）→ “下发到设备…” → DEV-001 → 输口令。
  2. 盯着 DEV-001 窗口，状态一变成“重启中”就点演示面板的 **“模拟断网”**（有 8 秒时间）。
  3. 等 DEV-001 窗口显示自检失败、回到原分区，“待上报事件”变成若干条未确认。服务端上 DEV-001 显示离线。
  4. （可选，多 20 秒）切到终端运行 `cat local/demo/device/DEV-001/outbox/events.jsonl`：这些未确认的事件就在磁盘文件里，每行一条，带序号和毫秒时间戳。
  5. 点 **“恢复网络”**。
- **看到**：几秒内 DEV-001 重新上线，待上报事件清零；服务端 DEV-001 升级状态 `ROLLED_BACK`，固件版本仍是 2.1.0；“设备事件…”里能看到序号连续的事件。
- **讲**：
  - 回滚完全由设备自己完成，**不依赖服务端在线**：新固件只是“待确认”，自检不过就清掉待确认标记、从旧分区启动，旧分区从头到尾没被动过，所以不会变砖（FT-13）。
  - 断网期间的事件先追加写进本地 outbox 文件并刷盘，再尝试发送，不只放内存（红线 1-5）；进程被杀掉重启后还在（证据包 A6 有断网中强制结束、重启后事件仍在的截图）。
  - 重新登录时服务端告诉设备“我已连续收到第几号”，设备按序号补传，服务端按（设备，序号）去重入库：不丢、不重、不乱序（FT-08、FT-09）。

### 场景 4：灰度发布与紧急停止（5:15 – 7:30）

- **操作**：
  1. “灰度发布”页 → “新建发布…” → 固件选 2.1.0，金丝雀按分组选 `canary`（只有 DEV-002）→ “建为草稿”。
  2. 选中这条草稿 → “开始灰度” → 输口令。
  3. DEV-002 走慢速链路，下载约 16 秒，进度条慢慢涨。下载到 30% ~ 60% 时点 **“■ 紧急停止”** → 确认。
- **看到**：发布状态“已终止”；DEV-002 “失败 3012 服务端取消升级”，仍运行 2.0.0；DEV-001、DEV-003、DEV-004 是全量批，状态“已取消，发布终止，未推送”。
- **讲**：
  - 灰度按设备分组：先推金丝雀，全部成功后观察 15 秒（演示配置；默认 30 秒），没有失败和告警才进入“待确认全量”，再由操作员确认全量（互锁 ③：没过灰度不能全量）。金丝雀任何一台失败或告警，发布自动暂停。
  - 互锁 ①：同一型号同时只能有一个发布在推；互锁 ②：设备在升级途中不重复推。
  - 紧急停止给正在升级的设备发 `UPDATE_CANCEL`：还没写 Flash 的放弃升级、保留旧固件；已经在写的照常写完再自检，A/B 保证它总能启动（7-6、10-5）。
  - 断网的设备不缓存、不盲发，记为“待确认”，恢复后要人工确认才推（10-6）。

### 场景 5：审计日志防篡改（7:30 – 9:15）

- **操作**：
  1. “退出登录”，用审计员 `audit01` 登录 → “审计日志”页。
  2. 往上翻能看到刚才的记录：开关打开、下发（带 `confirmed=password`）、DEV-001 的升级结果、紧急停止。点 **“校验日志完整性”** → 显示哈希链完整。
  3. 切到终端，回车运行 `demo/tamper_audit.sh`：它绕过程序，直接用 `sqlite3` 把最近一条发布类（ROLLOUT）记录的操作者改成 `intruder`（通常就是刚才那次紧急停止），并打印改前改后的内容和是第几条。
  4. 回到服务端，再点“校验日志完整性”。
- **看到**：提示“第 N 条的内容与它的哈希不符，这条记录被改动过”，N 和终端打印的一致。
- **讲**：
  - 每条审计日志的哈希 = SHA-256(上一条的哈希 ‖ 本条全部字段)，形成一条链：改任何一条，它自己的哈希对不上；删中间一条，序号断开；删掉末尾几条，和单独存放的检查点对不上（ST-33）。
  - 数据库管理员能改库，但改了一定会被发现，而且校验本身也记进审计日志。

### 收尾（9:15 – 10:00）

- **操作**（可选）：“运行日志”页按设备 DEV-001、关键字 `3007` 检索，看到自检失败那一行。
- **讲**：总结三条主线——传输安全（TLS 1.3 双向认证）、固件可信（签名、逐片哈希、防降级）、可靠可回退（A/B 回滚、断网落盘补传、灰度与紧急停止），全部由 78 条测试用例覆盖，证据在证据包里。

## 3. 可选场景（老师提问时用，每个 1 分钟以内）

| 提问 | 演示 | 要点 |
|---|---|---|
| “能装回旧版本吗？” | 操作员把 1.9.0（安全版本号 3）下发给 DEV-001 | 设备验签通过，但安全版本号低于本机最小值，`3003` 拒绝，**一个分片都不下载**；服务端不拦，防降级由设备自己把关 |
| “断点续传怎么体现？” | 新建灰度发布推 DEV-002，下载到一半点 DEV-002 的“模拟断网”，几秒后“恢复网络” | 进度从断点继续，不从 0 开始；已下载的分片在续传前重新校验 |
| “下载缓存被改了呢？” | DEV-002 下载中点“模拟断网”→“篡改下载缓存”→“恢复网络” | 续传前重验发现那一片不对，重下那一片；要是写入前整镜像校验不过就拒绝写入（`3005`） |
| “抓包能看到什么？” | 打开证据包里的 Wireshark 截图（`A2_ST-05_*`、`A2_ST-06_*`） | ServerHello 是 TLS 1.3 + AES-256-GCM；搜 `DEV-001`、`UPDATE_CANCEL` 等明文 0 次命中 |
| “服务端挂了设备会怎样？” | 终端 `demo/stop.sh server`，拖动 DEV-001 窗口 | 设备显示“离线运行（已断开，等待重连）”，界面照常响应；`demo/start.sh` 只会补起没在运行的进程，服务端回来后设备按退避自动重连（FT-10） |
| “写 Flash 时断电呢？” | DEV-001 勾“写入到 50% 时断电”，再下发 2.1.0（或 2.2.0）；进程退出后 `demo/start.sh DEV-001` | 重启后仍运行原固件，可以重新升级（FT-14） |

注意：`demo/start.sh` 会跳过已在运行的进程，所以停掉服务端后直接再运行 `demo/start.sh` 就能把它补起来；只想补起一台设备时带上名字：`demo/start.sh DEV-001`。

## 4. 卡住了怎么办

先判断 10 秒内能不能解决，不能就**重置后跳到下一个场景**：`demo/reset.sh && demo/start.sh`，重新登录（重置后“允许下发”回到关闭，要先用 `maint01` 打开）。

| 现象 | 原因 | 处理 |
|---|---|---|
| 窗口像卡住、内容不刷新 | macOS 上被挡住的窗口不重绘 | 点一下那个窗口或 Cmd-Tab 切过去，马上恢复；程序本身没卡 |
| 启动后服务端窗口没出现 | 窗口在终端后面 | Cmd-Tab；还没有就看 `local/demo/logs/server.out` 最后几行 |
| `server.out` 里“私钥解密失败” | 演示密钥口令输错 | `demo/stop.sh`，`demo/start.sh` 重输 |
| “OpenSSL 版本不对” | 换过 Qt 或 OpenSSL 后没清构建缓存 | `rm -rf build/dev` 重新构建（演示前一晚做，现场来不及就用兜底截图） |
| “端口已被占用” | 上一次没停干净 | `demo/stop.sh` 后再启动 |
| 某台设备一直离线 | 看 `local/demo/logs/DEV-00x.out`：许可证无效说明 setup 不是在这台电脑上跑的 | 在演示机上重新 `demo/setup.sh` |
| 下发被拒“允许下发未打开” | 服务端重启过，开关回到关闭 | `maint01` 登录打开，再换 `oper01` |
| 下发被拒“设备刚下发过 / 正在升级” | 互锁 ② | 等 10 秒再点；这本身就是可以讲的安全设计 |
| 新建发布被拒“该型号已有进行中的发布” | 互锁 ①，上一个发布还没结束或已暂停 | “灰度发布”页把它终止（输口令），或重置 |
| 场景 3 没赶上在“重启中”点模拟断网 | 回滚照样会完成并上报 `ROLLED_BACK` | 先讲回滚；断网补传改用“可选场景”里的服务端停止演示，或等 10 秒再下发一次 2.2.0 重来 |
| 场景 4 没赶上在下载中点紧急停止 | 金丝雀已成功，发布进入 15 秒观察期 | 在“观察期 / 待确认全量”时点紧急停止，结果同样是“已终止”、全量批全部“已取消”，照常讲 |
| 账号连续输错口令被锁 10 分钟 | 设计如此（ST-13） | 用 `maint01` 在“账号管理”页“解锁”；维护员自己被锁就重置 |
| 电脑完全跑不起来 | — | 打开兜底截图文件夹（证据包 `evidence/mac-20261118/` 里 A1、A5、A6、A7 开头的截图），按本脚本顺序讲 |

## 5. 分工建议

- 一人操作、一人讲：**A 操作服务端，B 讲**；讲到客户端（场景 3）时交换。
- 每个场景开头一句话说“要演示什么”，结尾一句话说“对应哪条要求”，老师容易跟上。
- 被问到代码时，按[代码讲解提纲](代码讲解提纲.md)找到对应文件和函数，现场打开讲。
