# 工业固件安全升级分发系统 —— 实施方案

> v0.2（2026-11-14）。按《项目落地要求任务书》和《资料大模板》调整：通信改为 TLS 1.3 双向证书认证，新增验收要求对照表和缺口清单，删去与设计文档重复的协议、密码和业务细节。
> 具体设计以[设计文档](系统设计说明书.md)和[通信协议文档](通信协议文档.md)为准。两份要求原件在 [requirements/](requirements/) 目录。

## 1. 一句话方案

用 **C++17 + Qt 6** 做三个程序：离线签发工具、分发服务端、设备客户端（可多开模拟多台设备）。通信走 **TLS 1.3 双向证书认证**（自建 CA，只启用 AES-256-GCM 套件），TLS 之上是自定义二进制帧协议（分帧、心跳、断线重连、帧序号）。固件包由 **RSA-3072-PSS 签名的 manifest** 和分片镜像组成，客户端先验签再下载，逐片校验哈希，并做防降级检查。设备端用 **A/B 双分区**模拟 Flash，启动失败自动回滚。服务端界面实时显示设备在线、心跳、登录状态和升级进度，提供带互锁、二次确认和紧急停止的灰度发布，以及防篡改的审计日志。设备状态事件先落盘再上报，断网恢复后按序号补传对账。

## 5. 技术栈

| 项 | 选择 | 理由 |
|---|---|---|
| 语言与构建 | C++17 + CMake | 跨平台，Windows 和 Linux 都能编 |
| 界面 | Qt 6 Widgets | 标准 C/S 桌面程序，表格和进度条现成；不做 Web 前端，避免被认定为 B/S |
| 网络 | Qt Network（QTcpServer、QSslSocket，非阻塞事件驱动） | 底层是 IO 多路复用，断线和超时都有信号 |
| 密码 | OpenSSL 3（TLS 1.3 和 EVP 接口） | 不自己实现算法 |
| 存储 | SQLite（Qt SQL） | 单文件，免部署 |
| 测试 | GoogleTest | 单元测试 |
| 打包与保护 | windeployqt、UPX、字符串加密、程序自签名 | 满足软件保护要求 |

## 7. 答辩演示顺序

先正常、再攻击、最后可靠性，约 8 分钟：上线与心跳（FT-01）→ 正常升级（FT-04）→ 断点续传与事件补传（FT-06、FT-09）→ 篡改固件被拒（ST-19）→ 降级被拒（ST-21）→ 异常证书与重放被拒（ST-03、ST-08）→ 抓包不可读（ST-06）→ 自检失败回滚（FT-13）→ 灰度失败暂停与紧急停止（FT-12、ST-26）→ 日志完整性校验（ST-33）。

## 8. 容易踩的坑

- 先下载完再验签：应先验 manifest 签名再下载；
- 只做哈希不签名：哈希必须受签名保护；
- 为了调试关闭证书校验，或使用超长有效期证书；
- 私钥文件用 OpenSSL 默认的口令加密方式：默认是无认证的 CBC 模式，会命中红线 1-4，须用 AES-256-GCM 封装；
- 私钥、口令写进代码、配置或提交进仓库：仓库历史也会被扫描；
- 口令只做一次 SHA-256；
- 帧头 Length 不校验就分配内存；
- 地址、端口、路径写死，只在本机回环地址上跑通；
- 断网数据只放内存；服务端一关客户端界面就卡死；
- 日志里打印密钥、口令、随机数或完整报文；
- 在界面线程里做大文件哈希和写盘；
- 声称性能好但没有实测数据；
- 只演示正常流程：攻击演示和证据同样计分。
