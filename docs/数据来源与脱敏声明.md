# 工业固件安全升级分发系统 —— 数据来源与脱敏声明

| 项 | 内容 |
|---|---|
| 文档版本 | v0.1 |

## 1. 声明

本项目在开发、测试、演示和留证的全过程中**不接入、不使用任何真实生产数据**。系统中出现的全部数据均由本组自行编造或由程序随机生成，不对应任何真实的工厂、人员、设备或生产批次。因此本项目不存在“把真实数据脱敏后使用”的环节，脱敏规则只用于约束日志和证据的内容。

## 2. 数据来源

| 数据 | 来源 | 示例 |
|---|---|---|
| 设备编号 | 自拟的顺序编号 | DEV-001 ~ DEV-050 |

## 3. 日志与证据的内容规则

即使数据都是模拟的，日志和证据仍按以下规则控制，以满足红线 1-7 和常见错误第 9、10 条：

| 内容 | 规则 |
|---|---|
| 私钥、口令、证书口令 | 任何日志、截图、抓包说明中都不得出现 |
| 随机数、会话密钥 | 不写入日志 |
| 完整报文 | 不写入日志；只记消息类型、长度、序号、错误码 |
| 哈希值 | 日志中只记前 8 位；告警证据中的完整哈希只针对模拟固件 |
| 网络地址 | 只出现私有地址；截图中若带出本机公网地址、无线网络名称则遮盖 |
| 主机名、系统用户名 | 测试主机使用中性名称（如 fwds-server、fwds-dev1）；截图中若带出个人用户名则遮盖 |
| 个人信息 | 截图不带出聊天窗口、邮箱、浏览器书签等无关内容；封面以外不出现姓名和学号 |
| 抓包文件 | 只在测试网段抓取，使用过滤条件只保留服务端端口的流量 |

## 4. 自检方法

提交前对证据包和日志目录逐文件执行（对应测试用例 ST-17）：

1. 文本搜索：私钥文件头（`PRIVATE KEY`）、`password`、`口令`、测试中用过的口令原文；
2. 文本搜索：本组成员的姓名、学号、个人用户名、真实主机名；
3. 抓包文件：确认只含测试网段地址和服务端端口，应用数据全部为 TLS 记录；
4. 截图：逐张人工检查是否带出第 3 节列出的内容；
5. 把搜索命令和结果保存为 `1-7_ST-17_证据自检结果.txt`，放入证据包。

任一项命中，先处理（重新采集或遮盖）再提交。
