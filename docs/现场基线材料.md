# 工业固件安全升级分发系统 —— 现场基线材料

| 项 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 依据 | 《项目落地要求任务书》第 2 类：六份基线材料中的 ①②③ |
| 其余三份 | ④ 威胁模型、⑤ 安全属性清单、⑥ 放弃项声明见[设计文档](系统设计说明书.md) 9.1 ~ 9.3 节 |

**说明**：本项目是教学原型，没有真实现场。以下是为设计和测试设定的一套**假想现场**，所有厂区、设备、编号、参数均为虚构，不对应任何真实工厂。设定的作用是让设计参数（超时、重试、并发、升级窗口）有据可依，并明确哪些东西系统不得改动。

## 1. 工况台账

假想现场：一座离散制造车间，两条产线，共 50 台待升级的嵌入式控制设备。

| 项 | 现场条件 | 对系统的影响 |
|---|---|---|
| 环境温度 | 车间 5 ~ 40 ℃；控制柜内最高 55 ℃ | 设备端不做长时间满负荷计算；校验与写入分步进行 |
| 湿度、粉尘 | 相对湿度 20% ~ 85%，无凝露；有金属粉尘 | 设备无风扇、存储为板载 Flash，写入次数有限，下载缓存与事件文件按需写入，不做无意义的频繁刷盘 |
| 供电 | 24 V 直流，经车间配电；无不间断电源，可能瞬时掉电 | 任一时刻断电都不能变砖：A/B 分区、原子写、启动计数回滚 |
| 网络 | 厂内工业以太网，百兆，与办公网隔离，不通互联网；电磁干扰下偶发丢包和秒级到分钟级中断 | 断点续传、退避重连、事件落盘补传；证书吊销用 CRL 而不是在线查询；时钟用厂内时间源 |
| 带宽占用 | 同一网络还承载生产数据，升级流量不得挤占 | 全量阶段并发上限默认 5 台，分片请求窗口 16 片 |
| 班次 | 两班制，8:00 ~ 24:00 生产；0:00 ~ 8:00 为维护窗口 | 发布由操作员在维护窗口人工发起；系统不做定时自动下发 |
| 人员 | 操作员（当班发布）、维护员（设备与证书管理）、审计员（事后核查） | 三种角色权限分离 |
| 设备主机 | 嵌入式控制器，内存与存储有限 | 分片 64 KB，流式校验，不把整个镜像读入内存 |
| 运维主机 | 车间机房内 1 台工控机，Windows 10/11，7×24 运行 | 服务端开机自启、进程守护、断电恢复 |
| 签发主机 | 研发侧 1 台离线电脑，不联网 | 固件包、证书、CRL 通过 U 盘拷贝 |

## 2. 设备协议台账

本系统与设备之间只有固件分发这一条通信链路，不读取、不写入设备的工艺点位和寄存器。

### 2.1 设备清单

| 设备编号 | 型号 | 位置 | 分组 | 说明 |
|---|---|---|---|---|
| DEV-001、DEV-002 | PLC-X200 | 产线 A | canary | 金丝雀组，先行升级 |
| DEV-003 ~ DEV-025 | PLC-X200 | 产线 A | line-A | |
| DEV-026 ~ DEV-050 | PLC-X200 | 产线 B | line-B | |

演示时实际启动的客户端数量少于 50 台，并发测试时启动全部。

### 2.2 协议与地址

| 链路 | 协议 | 地址与端口 | 方向 | 认证与加密 |
|---|---|---|---|---|
| 设备 ↔ 分发服务端 | FWDS v2（见[通信协议文档](通信协议文档.md)），承载于 TLS 1.3 | 服务端地址由配置给出，默认 TCP 9443 | 设备主动连接服务端 | 双向证书认证，`TLS_AES_256_GCM_SHA384` |
| 签发主机 → 服务端、设备 | 离线文件拷贝 | — | 单向 | 固件包有 FSK 签名；证书与 CRL 有 CA 签名 |

设备不开放任何监听端口，服务端不主动连接设备。

### 2.3 可访问对象与读写权限

本系统没有寄存器和点位，对应的是设备上可被远程影响的对象：

| 对象 | 内容 | 服务端权限 | 条件 |
|---|---|---|---|
| 设备状态 | 设备 ID、型号、固件版本、安全版本号、活动分区、升级状态与进度 | 只读（由设备上报） | 设备登录后 |
| 设备事件 | 进度、结果、告警 | 只读（由设备上报） | 设备登录后 |
| 非活动分区 | 新固件镜像 | 写（通过推送固件间接写入） | “允许下发”开关打开；操作员二次确认；通过服务端互锁；设备端验签、型号、防降级全部通过 |
| 活动分区、启动配置 | 正在运行的固件、`boot.json` | 无 | 只由设备本地 Bootloader 修改 |
| 设备私钥、许可证、内置公钥与根证书 | 身份与信任根 | 无 | 只在出厂初始化时写入 |
| 工艺参数、控制逻辑、输入输出点位 | 设备的生产功能 | 无 | 不在本系统范围内 |

## 3. 不可改约束清单

以下各项视为现场明令，本系统的设计和操作都不得改动或绕过。

| 编号 | 约束 | 类别 | 系统中的落实 |
|---|---|---|---|
| C-1 | 生产时段不得升级正在生产的设备；升级只在维护窗口进行 | 时序 | 不做定时自动下发；默认不下发，发布须人工发起并二次确认 |
| C-2 | 升级不得改动设备的工艺参数和控制逻辑配置 | 参数 | 固件包只写固件分区；协议中没有读写参数的消息 |
| C-3 | 任何情况下设备都必须能启动到一个可用固件 | 安全 | 只写非活动分区；自检失败或连续启动失败自动回滚 |
| C-4 | 不得降级到低于当前安全版本的固件 | 安全 | `security_version` 防降级，设备端强制 |
| C-5 | 设备只接受本厂签名的固件；签名私钥不得离开签发主机 | 安全 | FSK 离线保存；设备内置公钥验签；服务端不持有 FSK |
| C-6 | 设备不得开放入站端口，不得接入办公网和互联网 | 接线与网络 | 设备只主动外连服务端一个地址；全部在工厂内网 |
| C-7 | 不得改动现场网络拓扑、网段划分和交换机配置 | 接线与网络 | 系统只占用一个 TCP 端口，地址与端口可配置 |
| C-8 | 升级流量不得影响生产数据通信 | 时序 | 并发上限、分片窗口、拉取式流控 |
| C-9 | 设备 ID 与设备证书一一对应，出厂后不得更改 | 参数 | 登录时校验设备 ID 等于证书名称并与注册表指纹一致 |
| C-10 | 服务端不可用时现场设备必须照常运行 | 安全 | 降级运行：当前固件继续运行，事件落盘，恢复后自愈 |
| C-11 | 同一型号同一时间只允许一个发布在推送 | 时序 | 服务端互锁 |
| C-12 | 所有发布操作必须可追溯到人 | 管理 | 账号登录、角色分离、审计日志哈希链 |
