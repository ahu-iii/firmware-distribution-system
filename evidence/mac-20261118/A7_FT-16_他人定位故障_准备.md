# FT-16 他人定位故障：现场准备（A7）

FT-16 要求一位**没有参与开发**的同学只用服务端界面上的日志找出一次预设故障的原因。下面是演示前要准备的东西和现场流程，照着做即可。记录表在最后，做完后填好改名为 `8-5_FT-16_他人定位记录.md`。

## 演示前（开发者做，同学不在场）

1. 用 `local/ev` 这套脱敏演示环境（端口 19543，三个账号 maint01 / op01 / aud01）。
2. 预设故障：操作员 op01 在“固件库”页选 `PLC-X200 2.2.0（安全版本号 6）`，下发到 DEV-003。2.2.0 是 `--selftest-fail` 做的包，设备写入分区 b、重启自检失败后自动回到 2.0.0，结果 ROLLED_BACK 3007。
3. 等设备监控页 DEV-003 的升级状态变成 ROLLED_BACK 后，**切到“设备监控”以外的页**，不要让同学一眼看到结果。
4. 给同学审计员账号 aud01（只读，不能改任何东西）。

## 现场给同学的说明（只说这些）

> 刚才有一台设备升级没成功，请你只用这个程序里的“运行日志”和“审计日志”两页，找出是哪台设备、什么时候、为什么失败。不能看代码，可以随便用页面上的筛选条件。

不要提示设备 ID、错误码或关键字。开始计时。

## 预期能找到的线索（给开发者核对用）

| 页面 | 筛选条件 | 能看到的记录 |
|---|---|---|
| 审计日志 | 分类 UPGRADE，或关键字 `ROLLED_BACK` | DEV-003 升级结果 ROLLED_BACK 3007，发布号、包 ID |
| 运行日志 | 设备 DEV-003，级别 WARN | `device DEV-003 upgrade ROLLED_BACK code 3007 …`（自检失败） |
| 运行日志 | 关键字 `3007` 或 `回滚` | 同上，加上发布的说明 |

定位成功的标准：说出“DEV-003 在 ××:×× 升级到 2.2.0 时新固件自检失败，自动回滚到原固件（错误码 3007）”或意思相同的话。
